WHY NOW

生成能力正在商品化，
交付能力才是新稀缺。

以下是产品判断，不是市场规模或增长数据。

01

生成变快了，交付没有。

代码和内容可以在几分钟内出现，但目标对齐、范围约束、真实预览和验收责任仍然是稀缺能力。

02

Agent 变多了，责任更模糊。

多 Agent 只有在角色、权限、证据和 Gate 可被追溯时，才是产品能力，而不是一群同时说话的模型。

03

能力进入平台，成本也必须进入产品。

Provider、搜索、权益、预算和审计不能散落在用户终端；平台必须能失败关闭、脱敏并解释每次调用。

FROM INTENT TO ACCEPTANCE

不让 Agent 一路跑到“它觉得做完了”。

每一次前进都有可见产物、权限边界和用户决策。

  1. G0

    目标对齐

    用户决定到底要改变什么。

  2. G1

    问题与证据

    先分清事实、假设和空白。

  3. G2

    产品定义

    将用户价值变成可验收的产品合同。

  4. G3

    方案与体验

    让用户在开发前看见将要得到什么。

  5. G4

    开工授权

    定义范围、预算、权限和退出条件。

  6. G5

    用户验收

    预览、证据和 Reviewer 只辅助，不代替用户通过。

  7. G6

    发布授权

    对具体版本、区域、渠道和一次动作单独授权。

THE OWNER RULE

Codex Approval、Reviewer verdict 和自动测试都不能代替用户 Gate。

AGENT COLLABORATION

不是一个超级 Agent。
是一支有责任边界的交付组织。

01

Factory Lead

管理项目阶段、分工与交付节奏，不抢走用户决策权。

02

AI PM

把模糊想法收敛为证据、产品定义与明确取舍。

03

Builder

只在已批准 Workspace 内开发，不自动 push、deploy 或删除。

04

Reviewer

默认只读，独立核查预览、测试、边界与恢复证据。

ONE PLATFORM, THREE SURFACES

把体验、运营和证据分开，
才能真正托管。

01 · 访客 / 投资人

产品展示页

讲价值、产品机制、商业假设和版本下载信息。

不展示运营数据、内部进度、假客户或未批准价格。
02 · 受邀用户

用户 APP

只处理项目、阶段、授权、产物、恢复与账户安全。

用户不接触 Provider Key、Runtime、成本账本和 Tool Audit。
03 · 平台运营

管理后台

管理邀请、设备、Provider、风险、客服、审计与敏感操作复核。

只看运营元数据，不冒充用户，不默认读取项目正文。

COMMERCIAL POSSIBILITY

商业想象力来自可复用的交付机制，
不是被发明的数字。

愿景

个人产品交付

按月、季或单次交付权益；定价、额度、续费与退款规则均待验证。

待验证假设

团队决策治理

多人 Gate、角色权限、证据库与交付可追溯，尚未进入企业采购。

愿景

平台托管能力

统一 Provider、搜索、预算、风险与审计；对外代理或转售仍需书面授权。

远期愿景

可验收交付网络

将预览、Reviewer 证据、用户验收和发布授权连成交付协议。

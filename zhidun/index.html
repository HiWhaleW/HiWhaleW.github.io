01 / 背景与定位

三类真问题，一个根因

智盾面向约 120 名嵌入式工程师，覆盖多型号研发、外场排障和交付质检，主要解决型号知识易混淆、外场经验分散和跨环节数据难复用的问题。项目首期以 RAG + 固定 Workflow 完成知识问答并验证经验复用价值，随后将数据、权限和质量规则平台化，六项核心服务通过上线验收，并在此基础上由受约束 Agent 按任务动态调用。

建库阶段 · 6 策略（对应上方冷启动流水线）
序号策略阶段关键设计验收与协作边界
01数据治理P0原始材料留档；候选材料去重、分版本并补齐关键字段，显式区分疑似、已排除和已确认根因，避免把排查过程洗成最终结论。字段正确率约 85% → 95%；产品定知识口径和质量规则，业务专家确认，研发实现处理链路。
02知识建模与分块P0先形成可审核的 KnowledgeItem，再按查案例、找现象、取方案、做预检四类任务生成 chunk；不按统一字数盲切。产品定义任务和字段；命中片段必须能回到父级知识条目与原始证据。
03嵌入模型P0以中文召回质量、内网合规、时延、稳定性和索引重建成本作为选型标准。产品定标准与评测集；研发实测候选，最终选用 BGE Embedding。
04元数据P0chunk 继承型号、版本、审核状态、根因状态、风险等级和适用范围，为召回前硬过滤提供条件。型号或版本不符时不得进入候选池。
05索引分工P0结构化字段负责权限与型号版本边界，BM25 负责型号、版本和故障码等精确实体，向量索引负责口语化现象与语义相似案例。产品按 Bad Case 定义各通道适用场景和一致性规则；研发完成主表、关键词与向量检索实现。
06索引选型边界P1当前项目资料只确认向量召回能力，不把 HNSW / IVF 等底层实现写成既成事实；候选算法需在真实数据和固定评测集上比较。产品给出数据规模、更新频率、召回率、P95 时延和重建成本要求；研发完成基准测试并留存版本证据。

A · 建库阶段：把材料治理成可信知识
① 原始证据留档按时间保留消息、角色、日志、截图、附件和版本变化；清洗不覆盖原文，后续结论可以回指现场。
② 清洗与版本归一去模板噪声和重复记录，统一型号、版本与别名；保留“疑似 / 已排除 / 已确认”状态，不把中间判断改写成事实。
③ 建立 KnowledgeItem抽取现象、环境、适用型号、根因状态、方案、验证步骤、风险与来源；AI 生成候选，不能自行发布。
④ 专业人员确认工程师确认字段，技术主管审核结论与适用范围；只有 approved 且质量达标的知识才获得正式检索资格。
⑤ 按用户任务分块生成 summary / symptom / solution / precheck 四类 chunk；solution 保留必要重叠，避免操作与回滚要求被切断。
⑥ 建立检索表示结构化字段管权限与型号版本，BM25 管精确实体，向量索引管语义现象；所有 chunk 通过 knowledge_id 回到父级知识。
B · 在线阶段：从用户问题到可复核结果
⑦ 先定任务与边界识别用户是在查相似案例、找解决步骤还是做交付预检；型号或版本不清时先追问，不让模型猜。
⑧ 前置硬过滤在召回前校验权限、approved、质量分、型号版本与适用范围；越权、待审核和不适用内容不进入候选池。
⑨ 多路召回与重排BM25、向量和关联案例分别找候选，合并去重后由 Reranker 与业务规则排序；型号版本优先于表面语义相似。
⑩ 构造 Evidence Pack命中小块后补齐必要父级字段和原文邻接证据；去重、控 Token、标记冲突和根因状态，不把整张长工单直接塞给模型。
⑪ 来源约束生成模型只基于证据包组织答案，关键结论带来源与适用范围；证据不足或冲突时拒答 / 转人工，高风险操作不自动放行。
⑫ 反馈与回归Bad Case 先冻结输入、知识、模型、Prompt 和 Trace 并稳定复现，再归因；确认后进入版本化评测集，通过门禁才灰度发布。
AI PM 负责什么定义用户任务、知识状态、风险边界、拒答与人工接管条件、评测集、发布门槛和验收指标。
研发 / 数据 / 专家如何协作研发实现抽取、索引与运行链路；数据团队维护版本和质量；领域专家确认事实与最终放行。
产品判断：长工单处理的目标不是“切出更多 chunk”，而是防止中间假设进入正式答案，并让每条结论都可审核、可追溯、可复现、可回归。

序号策略阶段关键设计验收与协作边界
07查询转换P1识别用户要查资料、判断问题、生成路径还是预检；口语型号和曾用名归一到标准编码，同时保留原始实体。低置信度追问或降级，不猜型号、不擅自扩大适用范围。
08检索参数P1关键词通道管精确实体，向量通道管语义现象，关联案例通道补结构化关系。BM25 Top20 · 向量 Top30 · 关联案例 Top10；研发调参，固定集验证。
09上下文构造P0用于检索的块 ≠ 用于生成的证据包：小块负责命中，再补齐必要父级字段和原文邻接证据；去重、标冲突、控 Token，不把整份长工单直接塞给模型。正确证据必须进入最终上下文；过期、越权、疑似或冲突内容必须被过滤或显式标记。
10重排序模型P1BGE Reranker 对三路并集精排，再叠加业务特征：型号 / 版本强优先，质量分 / 根因状态中度，反馈轻度。审核状态决定资格而非名次；反馈不能覆盖硬约束。
11大语言模型P0模型只承担复杂归纳与来源约束生成；结构化校验优先走规则或小模型。产品定选型标准；研发实测候选，最终选用 DeepSeek-R1-Distill-Llama-70B。
12生成约束P1模型只基于 Evidence Pack 组织答案；疑似根因标注“需现场确认”，高风险操作转人工，证据不足或冲突时拒答。试点期最多使用 3 条 approved 来源摘要；关键结论带引用，任何规则变化都进入回归。

A · 这次 Agent 为什么这样调用
① 固定入口校验确定性 Workflow 校验用户角色、可访问范围和必填上下文；缺型号或版本时先追问，不启动 Agent 猜测。
② 调用产品型号查询把“E2200”归一为标准型号与当前固件范围。若别名不存在或版本不匹配，进入明确失败分支。
③ 调用知识检索带标准型号、版本和问题检索 approved 知识；返回 KnowledgeItem ID、根因状态、适用范围、来源与警告。
④ 读取结果再决策只有证据足以支持“已知问题”且适用范围一致，Agent 才继续；证据冲突或不足则拒答或转专业人员。
⑤ 调用预检候选生成依据型号、固件和交付场景生成检查项、来源、风险等级、验证方法与建议执行角色。
⑥ 高风险出口Agent 可以给出候选和证据，但涉及固件、参数修改或最终放行时，由确定性规则拦截并转交交付负责人确认。
⑦ 结果与反馈留痕返回带引用的历史案例和预检候选；用户反馈通过知识反馈提交服务记录，只进入分析与回归，不直接改写可信知识。
⑧ 没有调用另外两项服务运营指标查询和数据资产目录查询服务虽然稳定上线，但与本次任务无关。Agent 的价值是按任务选择必要服务，而不是每次调用全部六项。
AI PM 的产品决策定义任务输入、六项服务合同、允许调用条件、服务结果如何改变下一步、拒答 / 停止 / 转人工门槛及验收用例。
如何验收这个案例型号无法归一时不进入检索；只返回 approved 且适用的来源；无证据不判断；高风险操作与最终放行必须转人工；Trace 可回放。
产品结论：页面案例负责讲清“为什么这样决策”，Agent 运行轨迹 Demo 负责展示“实际调用顺序、参数、结果和分支”。现有 Demo 不是案例的替代品，而是案例的可交互证据层。

800+ · 约 200800+ 是历史候选材料池；约 200 是依据频次、风险和业务价值优先入审的高频知识。候选材料按来源记录去重；高频知识以 KnowledgeItem 为单位，需经过工程师确认与主管审核才可成为 approved 知识。800+ 不等于可信知识数；约 200 不等于自动生成后直接发布。
字段正确率约 85% → 95%型号、现象、根因、方案等关键字段与原始证据一致的字段占比。分子为抽样中正确字段数，分母为同一抽样口径下被核验字段总数；约 85% 为 AI 提取基线，规则与人工纠错后约 95%。不是 OCR 字符识别率，也不是回答准确率。
200 条评测集从独立历史问题中固定下来的离线回归样本，用于比较不同检索与生成版本。与知识审核集、Few-shot 示例分离；输入、期望证据、型号版本和关键失败条件冻结，困难样本不得删除。不是 200 条知识，也不是线上全部请求。
Top3 约 45% → 95%正确且适用的知识是否出现在检索结果前三位。分子为 Top3 内出现标准证据的评测问题数，分母为 200 条固定评测问题；同一数据集、过滤规则和判定标准下比较。不是生成答案正确率，也不代表所有问题都能回答。
用户有用率 80%+业务用户对一次有效结果明确标记“有用”的比例。分子为有用反馈数，分母为有明确有用 / 无用选择的有效反馈数；必须绑定 Query、版本和统计周期。不是 120 名用户中的活跃率，也不把未反馈自动算有用。
已知问题退回率约 −30%在“已知问题”限定口径下，交付因既有问题再次被退回的相对降幅。（基线期退回率 − 上线期退回率）÷ 基线期退回率；两期使用相同已知问题定义和交付样本规则。不是全部交付退回下降 30%，也不是减少 30 个百分点。
六项服务稳定上线知识检索、预检候选生成、运营指标查询、产品型号查询、知识反馈提交、数据资产目录查询。每项均通过研发实现、权限验收、调用方联调、SLA / 降级、审计留痕与固定集回归后计为稳定上线。不是六个 Agent，也不是接口能返回 200 就算上线。
46–70 万元 / 年规模化阶段的年化节省目标区间。按减少的重复研判工时与已知问题退回返工成本建立业务台账，并以实际使用量和财务确认口径年度化验证。是目标值，不是已经实现的财务收益。
